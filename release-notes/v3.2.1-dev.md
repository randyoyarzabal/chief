# Chief v3.2.1-dev Release Notes

## 🚀 What's New

### Live progress: no more repeated step lines

- Fixed: in an interactive terminal, every step that ran a command (for example in `chief.release_publish`) printed a job notice such as `[1] 47485`. That left the step's "running" line behind, so each step appeared twice. Step commands now start from a short-lived subshell, so the shell no longer prints job notices and each step shows as one line.

### Spinner rebuilt on the core progress helper

- `chief.etc_spinner` now runs on a new core spinner (`__chief_spin`), with the same arguments (`<message> <command> <output_variable>`). Changes you'll notice:
  - New default look: a smooth spinner in front of the message, like the step progress. `--legacy` keeps the original look, `message [|]` turning through `| / - \`, at the original pace.
  - No more `[1] 12345` job notices or leftover spinner text (for example the `Loading SSH keys... [|]` that could stay on screen at start-up).
  - Returns the command's exit code (it used to always succeed), so `if chief.etc_spinner ...; then` works.
  - Output containing quotes (`it's`) is captured correctly; it used to break the result.
  - An `exit` inside the command no longer exits your shell.
  - No animation when output isn't a terminal.
- Chief's own start-up, `chief.ssh_load-keys` and the update check use the core spinner directly, so they keep working even if you turn off the `etc` plugin (`chief.plugin disable core.etc`).
- Documented for plugin authors: "Progress Indicators" in docs/plugin-development.md covers the spinner (one command) and the step progress helpers (several steps, with `✓` / `↷` / `✗`, questions, `--dry-run` and a summary), with examples. The old example there passed a process ID to the spinner, which never worked; it's replaced.
- Tests: the spinner's output, exit code, quotes, the `chief.etc_spinner` wrapper, `--legacy` (all four frames), and no job notices at a real interactive prompt.

### Update branch follows your checkout ("auto")

- New default `CHIEF_CFG_UPDATE_BRANCH="auto"`: Chief updates from whatever branch its own checkout is on. Moving between stable and development is just `git -C ~/.chief switch dev` (or `main`), with no config change. On a tag or detached HEAD, `main` is used.
- The banner's `tracking:` line and the start-up hint follow it too, marked `auto` (for example `tracking: dev (bleeding-edge, auto)`), and the hint shows the command to switch.
- A branch name still pins it, as before: `chief.config-set update_branch main` (or `dev`, or any branch); `chief.update` then offers to switch the checkout back if it differs. `chief.config-set update_branch auto` returns to following the checkout.
- The installer sets `auto` (so installing from `dev` follows `dev`) instead of writing the branch name.

### Reminder when Chief's files changed since your shell loaded them

- The banner (start-up, `chief.help`, `chief.status`) now notes when the Chief version on disk differs from the one your shell loaded, for example after switching branches by hand, a `git pull`, or an update from another terminal: *"~/.chief is now v3.2.0, but this shell loaded v3.2.1-dev. Run: chief.reload"*. Silent when they match.
- The branch-switching instructions (README, getting-started) now include `chief.reload`.

## 📋 Upgrade Notes

- **`chief.etc_spinner` now returns the command's exit code.** It used to always succeed. If a script or plugin runs with `set -e` (or checks `$?` after the spinner) and relied on that, a failing command now stops it or reports failure. To keep the old behavior where needed, add `|| true`:
  ```bash
  chief.etc_spinner "Working..." "some_command" result || true
  ```
  (`result` is the name of a variable, given without `$`, that receives everything the command printed; use it afterwards as `$result`.)
- **Update branch:** existing configs keep their pinned `CHIEF_CFG_UPDATE_BRANCH` (for example `"main"`), so nothing changes until you opt in with `chief.config-set update_branch auto`.
- Prefer the old spinner look? Add `--legacy`: `chief.etc_spinner --legacy "Working..." "some_command" result`.
