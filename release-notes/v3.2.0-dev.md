# Chief v3.2.0-dev Release Notes

## What's New

### Core vs user plugins

- Core plugins: built-in, not editable via `chief.plugin`. User plugins: from `CHIEF_CFG_PLUGINS_PATH`, editable and listed by `chief.plugin -?`.
- Banner and help show Core vs User plugins separately.

### Enable/disable plugins

- `chief.plugin enable|disable [core.]<name>`; `chief.plugin status`. Config: `CHIEF_CFG_PLUGINS_DISABLED_CORE`, `CHIEF_CFG_PLUGINS_DISABLED_USER` (comma- or space-separated).

### chief.reload

- Plugin names color-coded (green loaded, yellow skipped).

### chief.status

- New command: prints the Chief banner followed by a stats summary (function count, core and user plugins, enabled/disabled state). Handy for a quick health check without reloading.

### Terminal color handling

- ANSI colors are now emitted only when stdout is a capable TTY (`TERM` set and not `dumb`). Output piped to a file, `grep`, or CI logs is plain text.
- Set `NO_COLOR=1` to disable colors everywhere; set `CHIEF_FORCE_COLOR=1` to force colors even when stdout is not a TTY.
- The same policy applies to the core library, the OpenShift plugin, and the `install.sh`/`uninstall.sh` scripts.

### chief.plugin symlink

- `chief.plugin <name> <existing_file_path>` creates a symlink so an existing script loads as a plugin.
- When the existing file lives inside the plugins directory (`CHIEF_CFG_PLUGINS_PATH`), Chief uses a **relative** symlink target so the link stays valid after `git clone` on another machine (remote plugins repo / shared dotfiles). A file outside the plugins directory gets an **absolute** target, and Chief prints a note that the link is not portable.
- Fixed broken links when the plugins directory is reached through a symlink (for example `~/chief_plugins` → `~/code/.../common`). Chief used to compute the relative target from the symlinked path, but the OS resolves it from the real directory, so the link pointed at a file that did not exist. Paths are now resolved to their real locations first.
- Chief now checks that a new link actually resolves. If a relative target does not, it falls back to an absolute one; if that fails too, it removes the link and reports an error instead of claiming success.

### chief.whereis

- Now searches plugins that are symlinks (such as ones created with `chief.plugin <name> <file>`) and plugin directories reached through a symlink. Previously they were skipped, so a loaded function showed "No definitions found".
- Fixed `~/.bashrc.d` / `~/.bash` scanning, which skipped `*.sh` files because of a `find` operator-precedence bug.
- Commented-out lines (for example `# my_func() does X`) no longer count as definitions or trigger a false "Multiple definitions" warning.

### Cursor / GUI editor

- `--code` / `--vscode` prefer Cursor when `cursor` is in PATH. Config: `CHIEF_CFG_EDITOR_GUI_CMD` to override.

### chief.update

- After update, Chief may prompt to run `chief.config-update` if the config template changed.

### Version bump (README)

- README update and warning box work with more title/section variants; bump more tolerant of format.
- Badges are now rewritten by meaning instead of by global find-and-replace: **Download Release** and **Stable** always show the latest released version, and **Dev Branch** always shows the in-progress `-dev` version. Previously a `next-dev` bump turned all three badges into the dev version.
- Fixed a false "Already up to date" skip of `VERSION` during `release` (the check matched `v3.2.0` inside `v3.2.0-dev`).

### Test suite and CI

- New `tests/bump-tests.sh`: runs `__chief.bump release` and `next-dev` on a scratch copy and asserts VERSION, badge, release-notes, and config outcomes. Runs on Linux and macOS in CI (BSD vs GNU sed).
- ShellCheck is now a real gate at error severity (previously informational only and hidden). Warnings still only show with `-v`. `shellcheck` is optional locally; the suite skips it with a warning when not installed.
- Removed duplicate tests: plugin sourcing was tested in both `source-tests.sh` and `plugin-tests.sh`; `chief.sh --lib-only` loading was tested in both `source-tests.sh` and `integration-tests.sh`. Removed two integration checks that could never fail.
- Workflow: the apt cache action is pinned to a commit SHA instead of `@latest`; macOS uses the preinstalled shellcheck instead of a Homebrew install on every run.

### Banner customization

- Two new config options let you hide individual banner header items without turning the whole banner off (the ASCII logo stays put either way): `CHIEF_CFG_BANNER_SHOW_PLUGINS` toggles the `plugins:` line and `CHIEF_CFG_BANNER_SHOW_TRACKING` toggles the `tracking:` line. Both default to `true` and only apply when `CHIEF_CFG_BANNER=true`.

### Bash version check (macOS)

- Chief needs Bash 4.0+, but macOS ships 3.2. On the system bash the only symptom used to be cryptic `declare: -A: invalid option` / `declare: -g: invalid option` errors at start-up from plugins.
- Chief now warns at start-up (stderr, before plugins load) when it runs under Bash older than 4.0. The message names the running Bash, and on macOS gives the fix: `brew install bash`, then make the terminal use it (set the terminal's command to `/opt/homebrew/bin/bash -l`, or add a small re-exec snippet to the top of `~/.bash_profile`). If a Homebrew Bash is already installed it says so and skips the install step. It never blocks loading.
- New config option `CHIEF_CFG_BASH_WARN` (default `true`; `chief.config_set -y BASH_WARN=false` to silence).
- `tools/install.sh` prints the same guidance when run under Bash older than 4.0 (informational; the install continues).
- Docs: new "macOS: install a newer Bash" section in the getting-started guide; the troubleshooting entries now mention the `declare` errors.

### Git plugin

- `chief.git_init <repo_url>`: initial commit of current directory to a repo (init, remote, add, commit, branch, pull, push). Refuses if already a repo.
- `chief.git_commit`: warns before committing staged files that exceed a size threshold (default 50 MB, configurable via `CHIEF_CFG_GIT_COMMIT_WARN_MB`). Interactive prompt offers three options: commit anyway, unstage and add the file(s) to `.gitignore`, or abort. Previously tracked files are also removed from the index with `git rm --cached`. Use `-f`/`--force` to skip the check. In non-interactive shells the commit is aborted when large files are detected.
- `chief.git_commit`: the initial `git pull` is now best-effort. If the pull fails (for example merge conflicts or unmerged files), a warning is printed and the commit and push still run instead of aborting.

### Secrets plugin and Vault plugin

- **Secrets plugin** (`secrets_chief-plugin.sh`): Encrypted bash secrets file (env vars, functions). Backends: **Ansible Vault** or **GPG** (symmetric AES256). Commands: `chief.secrets_file-edit`, `chief.secrets_file-load`. Backend chosen when creating; auto-detected when loading/editing. Default files: `.chief_user-secrets`, `.chief_shared-secrets`.
- **New GPG backend**: Encrypted secrets files were previously Ansible Vault only. You can now use GPG symmetric encryption (AES256, ASCII-armored), so no Ansible install is required.
  - Choose the backend when creating a file with `--backend=gpg` or `--backend=ansible`. If you do not specify one, GPG is used when `gpg` is in PATH, otherwise Ansible Vault.
  - Existing files are auto-detected as Ansible Vault or GPG. Do not pass `--backend` when editing or loading.
  - Non-interactive password: GPG uses `CHIEF_SECRETS_PASSWORD_FILE`; Ansible Vault continues to use `ANSIBLE_VAULT_PASSWORD_FILE`. Otherwise you are prompted.
  - Existing Ansible Vault files keep working unchanged. To switch a file to GPG, decrypt it and recreate it with `--backend=gpg`.
- **Clearer GPG errors**: `chief.secrets_file-edit` and `chief.secrets_file-load` no longer report every GPG failure as a wrong password.
  - If the file is GPG-encrypted and `gpg` is not installed, Chief now stops before asking for a password and says so, with an install hint for your platform (for example `brew install gnupg` on macOS). Previously the missing binary was hidden and looked like "GPG decrypt failed (wrong password or file)".
  - When `gpg` runs but fails, Chief shows gpg's own message. It only says "wrong password" when gpg reports a bad passphrase or decryption failure. The same applies to the re-encrypt step at the end of `chief.secrets_file-edit` (previously a bare "GPG encrypt failed.").
  - Ansible Vault files get the same treatment. `chief.secrets_file-load` used to hide `ansible-vault` errors and report "password or syntax" for everything. It now decrypts first and reports separately a wrong vault password, a missing vault password (with a hint to set `ANSIBLE_VAULT_PASSWORD_FILE`), any other `ansible-vault` error (with its message), or a syntax error in the decrypted content. `chief.secrets_file-edit` adds a clear failure line after `ansible-vault edit` fails.
- **Vault plugin** (`vault_chief-plugin.sh`): HashiCorp Vault only. Commands: `chief.vault_read-secret`, `chief.vault_write-secret`, `chief.vault_list-secrets`. Requires `vault` CLI, `VAULT_ADDR`, `VAULT_TOKEN` (or `VAULT_TOKEN_FILE`).

## Deprecations and breaking changes

- **Deprecated**: `chief.vault_file-edit` and `chief.vault_file-load`. Use `chief.secrets_file-edit` and `chief.secrets_file-load`. Old names still work but print a deprecation warning.
- **Deprecated**: File names `.chief_user-vault` and `.chief_shared-vault`. Use `.chief_user-secrets` and `.chief_shared-secrets`. Legacy names still work; renaming shows a deprecation warning.
- **Breaking**: The former "vault" plugin (encrypted file) is now the **secrets** plugin. The **vault** plugin is now HashiCorp Vault only (read/write/list secrets via Vault CLI). Disable separately: `CHIEF_CFG_PLUGINS_DISABLED_CORE` can include `"secrets"` and/or `"vault"`.

## Upgrade notes

- Use `chief.secrets_file-*` for encrypted bash secrets; `chief.vault_*` for HashiCorp Vault. Migrate from `chief.vault_file-*` and rename `.chief_*vault` to `.chief_*secrets` when convenient.
- After `chief.update`, run `chief.config-update` if prompted. Use `chief.plugin status` to see enabled/disabled plugins.
