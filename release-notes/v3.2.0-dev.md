# Chief v3.2.0-dev Release Notes

## 🚀 What's New

### Core vs user plugin distinction

- **Core (built-in)**: plugins shipped with Chief (`$CHIEF_PATH/libs/core/plugins`); not editable via `chief.plugin`.
- **User plugins**: your scripts from `CHIEF_CFG_PLUGINS_PATH`; created/edited with `chief.plugin` and the only ones listed by `chief.plugin -?`.
- Banner, `cf.help plugins`, hints, and `cf.help --compact` now show **Core (built-in)** and **User plugins** as separate lines/sections (and plugin counts are fixed).

### Enable/disable plugins

- **`chief.plugin enable|disable [core.]<name>`**: enable or disable a plugin; use `<name>` for user plugins, `core.<name>` for core plugins (e.g. `chief.plugin disable core.ssl`).
- **`chief.plugin status`** (or `list`): show enabled/disabled state; documents `<name>` vs `core.<name>` with examples.
- **Config**: `CHIEF_CFG_PLUGINS_DISABLED_CORE` and `CHIEF_CFG_PLUGINS_DISABLED_USER` accept **comma- or space-separated** names; empty/unset = all plugins enabled. Config template and parsing support both formats.
- Disabled plugins are skipped on load and excluded from plugin getters and stats.
- **Documentation**: Enable/disable is documented in Configuration (config vars + subsection), User Guide (plugin management and commands), Reference (plugin management block), and README (Discovery & Help).

### chief.reload output

- Plugin names in reload messages are **color-coded**: green for loaded, yellow for skipped (disabled). Colors render correctly in the terminal (no raw escape sequences).

### Plugin symlink for existing libraries (`chief.plugin`)

- **New**: `chief.plugin <name> <existing_file_path>` creates a symlink in the plugins directory so an existing script is loaded as a Chief plugin.
- Example: `chief.plugin pl /path/to/pl.sh` → `pl_chief-plugin.sh` in your plugins dir points to the existing file; Chief loads and edits it as usual.
- Does not overwrite an existing regular plugin file; use a new plugin name or remove/rename the file first.
- Help text and examples updated; see `chief.plugin -?`.

### Cursor / GUI editor support for `--code`

- **`--code` / `--vscode`** now prefer **Cursor** when the `cursor` CLI is in PATH, then fall back to VSCode `code`.
- New config **`CHIEF_CFG_EDITOR_GUI_CMD`**: set to `"cursor --wait"` or `"code --wait"` to force which editor is used for `chief.plugin ... --code` and `chief.edit-file ... --vscode`.
- Documented in config template; no config needed if Cursor shell command is installed.

### chief.update and config template

- **`chief.update`**: After a successful Chief update, if the config template has changed, Chief prompts to run **`chief.config-update`** so you can add new options to your config without editing by hand.
- **`chief.config-update`**: Name used consistently in prompts, help, and hints for updating your config from the template.

### Version bump README handling (`__chief.bump next-dev`)

- **Fixed**: README.md update no longer fails when title is `# Chief` (no 🚀) or section is `## Quick Install` (no ⚡).
- **Fixed**: Warning box insert uses Perl instead of sed for macOS/Linux compatibility.
- Install-block replacement is optional; bump succeeds even if that block pattern does not match.
- "Content correct" check for next-dev accepts both `# Chief (Development Version)` and `# 🚀 Chief (Development Version)`.

### Git plugin: `chief.git_init`

- **New**: `chief.git_init <repo_url>` initially commits the current directory to a repository.
- Runs: `git init`, `git remote add origin <url>`, `git add .`, `git commit -m "Initial commit"`, `git branch -M main`, `git pull origin main --rebase`, `git push -u origin main`.
- Refuses to run if the current directory is already a Git repo; supports `-?` / `--help`.
- Documented in plugin help, README, and docs index.

## 📋 Upgrade Notes

### For Users

- **Core vs user plugins**: Banner and `cf.help plugins` separate core (built-in) from user plugins; only user plugins are editable and listed by `chief.plugin -?`.
- **Enable/disable**: Use `chief.plugin disable core.ssl` or set `CHIEF_CFG_PLUGINS_DISABLED_CORE` / `CHIEF_CFG_PLUGINS_DISABLED_USER` (comma- or space-separated) in your config; `chief.plugin status` shows state. See docs (Configuration, User Guide, Reference, README).
- After **`chief.update`**, if the config template changed, you’ll be offered **`chief.config-update`** to merge new options into your config.
- Use `chief.plugin myname /path/to/existing-script.sh` to symlink an existing script as a plugin.
- Use `chief.plugin mytools --code` (or `--vscode`) to open in Cursor when the `cursor` command is available; set `CHIEF_CFG_EDITOR_GUI_CMD` to override.

### For Developers

- This is a development version; features and changes will be documented as they are implemented.
- Bump script is more tolerant of README format variations.
